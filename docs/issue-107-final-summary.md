## 🎯 Ключевые рекомендации

### Архитектура решения

```
poh-coding-standards (отдельный репозиторий)
├── universal/           # Универсальные правила
├── python/              # Язык-специфичные
├── javascript/          
└── go/                  
    ↓ git submodule (зафиксированный commit)
Репозиторий-потребитель
├── .standards/          # Submodule
├── .standards.overrides/ # Локальные расширения
└── .standards-config.toml # Конфигурация
    ↓ HTTP/MCP
MCP-сервер (для продакшена)
├── search (vector search)
├── get (file retrieval)
└── validate (LLM checks)
```

### Технические решения

| Аспект | Рекомендация | Обоснование |
|--------|-------------|-------------|
| **Подключение** | Git Submodule + CI-проверка | Детерминизм + независимость |
| **Расширения** | `.standards.overrides/` + config | Гибкость + явность |
| **Интеграция** | Инъекция в промпт → MCP-сервер | Пошаговый подход |
| **Валидация** | Автоматическая (LLM) + Human review | Качество + масштабируемость |
| **Формат** | Markdown + Frontmatter | Человекочитаемость + структура |

## 🔍 Ключевые находки исследования

### 1. Проблема подтверждена
- **Свидетельство:** PR #97/#105 — обход декларативных паттернов хардкодом
- **Причина:** Каждый агент/репозиторий импровизирует стандарты по-своему
- **Последствие:** Архитектурная непоследовательность

### 2. Решение уже частично существует
- Текущая система использует `AGENTS.md`, `.claude/skills/`, volume-монтирование
- Но эти решения фрагментированы и не систематизированы
- Нужен единый подход

### 3. Техническое решение проверено
- Git Submodule — надёжный механизм с детерминизмом версий
- MCP-сервер — масштабируемое решение для поиска правил
- Markdown + Frontmatter — баланс человекочитаемости и структуры
