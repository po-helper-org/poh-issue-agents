# Мультирепо через GitHub App — installation определяется по репозиторию

## Ситуация

Сервис следил за одним репозиторием; нужен произвольный набор репозиториев без правки
конфигурации на каждый. Ручной `GITHUB_INSTALLATION_ID` не масштабируется.

## Причина

PAT-токен один на всё, а App-модель требует installation-токен на каждый репозиторий.

## Решение

GitHub App с четырьмя переменными (id приложения, ключ `.pem` в base64, секрет вебхука,
список репозиториев). Installation-токен получается по репозиторию:
`GET /repos/{repo}/installation` → `POST /app/installations/{id}/access_tokens`,
кэш по репо (~55 минут) под lock. Allowlist `ISSUE_AGENT_REPOS` с масками `owner/*`,
`*`, пусто = любой установленный; вебхук отвечает 200 без старта воркфлоу на чужие
репозитории. PAT остаётся dev-фолбэком.

## Как проверить

Тесты `test_repos` (маски) и `test_github_client_auth` (per-repo кэш, base64-ключ,
приоритет заголовков).

## Уроки

Ключ удобнее возить base64-переменной, а не файлом; allowlist с масками — дешёвая граница
для дорогих прогонов. Подмечено позже (PR 47): заданный PAT молча выключает App-путь —
такое перекрытие обязано предупреждать.
