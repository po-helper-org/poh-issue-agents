# Триаж отвечает БФТ-документом, а не свободным текстом

## Ситуация

Триаж отвечал на запрос функционала свободным текстом «Ситуация — Ограничание — Варианты
решения — Оценка сложности»: в нём нет сценария приёмки, границ и открытых вопросов,
зато есть «варианты решения» — проектирование вместо постановки.

## Причина

Формат ответа не был зафиксирован; модель достраивала структуру сама.

## Решение

Запрос функционала получает БФТ быстрого прохода по формату навыка писателя: Цель (WHY
вперёд) → How to demo → Открытые вопросы → Границы → таблица требований на дословных
цитатах. Две команды, две цены: `/bft` — один вызов модели (в модель уходит вся
переписка Issue, включая прежние редакции, иначе замечание «во втором пункте не так»
не к чему отнести; ответ — редакция N+1, прежние остаются в треде); `/bft-deep` —
канонический пайплайн внутри клона репозитория, артефакты в ветку `bft-research/issue-N`,
повторный вызов дорабатывает тот же документ, id не перенумеровываются. Равноправные
триггеры метками `run:bft` / `run:bft-deep`. БФТ не двигает фазу Issue.

## Как проверить

Команда в тестовом Issue: структура документа соответствует формату, требования
опираются на цитаты постановки.

## Уроки

Формат ответа агента — часть постановки, а не вкус модели; редакции накапливаются в треде,
а не заменяются.
