# Почему событие не доехало — диагностика конфига вебхука

## Ситуация

Когда событие GitHub не доходило до контура, разбираться было нечем: allowlist, режим
авторизации и достижимость Temporal проверялись разрозненно и вручную.

## Причина

Сервис фильтровал события по allowlist молча (уровень info); образы не копировали
каталог `scripts/` — диагностический скрипт внутри контейнера не нашёлся бы, хотя именно
там он осмыслен (читает окружение сервиса). Попутно выяснилось: заданный `GH_TOKEN` молча
подменял GitHub App — всё публиковалось от владельца токена без предупреждения.

## Решение

`scripts/diag.py`: действующий allowlist и результат его разбора, режим авторизации,
реальная проверка связи с Temporal; флаг `--repo owner/name` прямо отвечает, доедет
событие или отфильтруется и по какой записи. Секреты не печатаются никогда — только
«задан / не задан». Отброс по allowlist поднят до warning и оставляет след — воркфлоу
`webhook-drop-*` с причиной и действовавшим списком. `COPY scripts/` добавлен в оба
Dockerfile; предупреждение о PAT рядом с App-путём.

## Как проверить

`docker compose exec webhook python scripts/diag.py --repo owner/name`; код возврата
0 — конфиг рабочий, 1 — Temporal недостижим или авторизация не настроена.

## Уроки

Диагностика обязана жить в том же окружении, что сервис; молчаливый фильтр — главный
источник «пропавших» событий; перекрытие механизмов аутентификации предупреждают явно.
