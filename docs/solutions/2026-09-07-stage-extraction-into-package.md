# Стадия «Разработка» уехала в пакет — перенос без остановки контура

## Ситуация

Код стадии разработки дублировался: жил в репозитории и в новом пакете. Аудит стадии
нашёл разрыв: код жил в четырёх местах, и правку вносили не туда, где она доедет.

## Причина

Перенос большой стадии нельзя сделать одним PR без риска смешать поломку установки
с поломкой импортов.

## Решение

Последовательность: пометка «образ собирается не отсюда» шапкой Dockerfile (правку вносят,
открыв файл, — увидеть её надо там же); установка пакета пином на полный SHA при живых
копиях (проверка сборки отдельно от перестановки импортов; пуш тегов из среды переноса
отклонялся git-шлюзом — пин SHA даёт ту же неподвижность); перестановка импортов
и удаление копий — точка невозврата (23 места нашёл греп, двадцать третье — относительный
импорт — нашёл прогон тестов: под шаблон поиска он не подпадал); переэкспорт типов
(пересекающие границу Temporal данные — формат сообщения: второе совпадающее объявление
не падает, а молча отдаёт словари вместо объектов — расхождение проявится далеко от
причины); исполнение пакетом через порты и мост адаптеров (адаптеры делегируют модулям:
связывание функций при сборке оставило бы неподключёнными подмены в тестах); отдельная
очередь воркера для стадии. По пути найдено: вебхук не стартовал три дня — его
requirements не обновили при переносе типов, контейнер в вечном рестарте; событие GitHub
не доходило ни в каком виде, снаружи «вебхук не отвечает».

## Как проверить

CI зелёный на каждом шаге; `docker compose ps` — оба контейнера живы; гвард проводки
воркера проходит.

## Уроки

Большой переносят стадиями: установка → импорты → исполнение → очередь; у каждой
точки невозврата — свой PR и зелёный CI до и после; requirements всех образов, тянущих
общие типы, меняются вместе.
