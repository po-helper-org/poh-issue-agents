# Сорванная разработка выкладывает работу черновым PR

## Ситуация

Агент отработал тринадцать минут и внёс правки, затем упали три теста из семидесяти трёх.
Ветки нет, PR нет, диффа нет: публикация идёт после тестов, а `finally` делает только запись
эпизода — работа и токены списаны без следа. У анализа такая защита уже была; у разработки
эквивалента не было.

## Причина

Порядок шагов: тесты → публикация; красные тесты отменяли публикацию целиком.

## Решение

Признак черновика у публикации рабочего дерева; активность `dev_publish_partial` —
повторяет подготовку дерева, открывает черновой PR с причиной в теле и комментарием,
который прямо называет прогон сорванным. Активность гасит собственные отказы: прогон уже
сорвался, подменить его причину своей ошибкой она не имеет права. Повторный прогон
обновляет прежний PR (422 «уже существует» обработан). Сначала спека с требованиями D1–D14,
потом реализация.

## Как проверить

Тесты частичной публикации (включая e2e); сорванный на тестах прогон оставляет черновой PR.

## Уроки

Красные тесты — не повод списывать работу: черновик с причиной лучше нуля;
спасательная активность не имеет права падать сама.
