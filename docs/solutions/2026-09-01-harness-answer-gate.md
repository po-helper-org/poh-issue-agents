# Входной гейт критерия приёмки и команда ответа контуру

## Ситуация

Живой прогон: задача с разделом приёмки и блоками «было / должно работать» прошла весь
цикл — план, разработка, PR, круг правок, мерж, закрытие; приёмка всё это время отвечала
«проверять нечем» (заголовок раздела был на русском, распознаватель принимал только
английские формы). Дорогая стадия запускалась без прочитанного критерия.

## Причина

Гейта на входе не было: отсутствие сценария контур превращал в молчаливое «проверить
не можем» после всей работы; ответить контуру на вопрос можно было только обычным
комментарием без структуры.

## Решение

Без прочитанного критерия дорогая стадия не начинается: контур предлагает 2–3 готовых
варианта сценария и принимает ответ командой `/harness-answer` — номером либо своим
текстом. Состояние вопроса разделено по обязанностям: содержание — блоком в теле Issue,
прогон хранит только идентификатор (копия в обоих местах расходилась бы при первой правке
руками). Журнал решений только пополняется: правка прежнего ответа добавляет запись,
отменяющую старую, — история задачи обязана отвечать, что решали и почему передумали.
Толкование свободного ответа видит журнал целиком. Команда общая: тем же способом контур
спрашивает про границы MVP, выбор плана, спорное решение. Разобраны граничные случаи:
два вопроса разом, пустая команда, ответ вписан руками, потерянный прогон при живой
задаче, отказ записи.

## Как проверить

Тесты гейта, команды и толкования ответа (включая e2e); живая задача без сценария
останавливается гейтом до разработки.

## Уроки

Дорогая стадия без критерия приёмки — заранее списанные деньги; вопросы контура —
структурная команда, а не свободный текст; журнал решений не затирается.
