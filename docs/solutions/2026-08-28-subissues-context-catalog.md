# Под-задача как инструмент разбиения, контекст — каталогом через git

## Ситуация

Контур заводил Issue на каждую находку: 221 из 267 Issue репозитория созданы им самим,
прирост ~30 в сутки. Работа шла в под-задачи как в трекер, а не как в разбиение на итерации.
Постановка резалась потолками по символам — часть контекста не доезжала до исполнителя.

## Причина

Модель «находка = новая задача» не ограничивала рост; потолки символов были единственным
механизмом усечения контекста.

## Решение

Под-задача живёт только на время шага и закрывается вместе с ним; находки вне границ MVP
уходят в секцию GROW тела родительского Issue, не заводя новых. Контекст едет исполнителю
каталогом `.harness/` через git (plan, requirements, howtodemo, decisions, карта контекста) —
без потолков символов. Разбор плана маскирует заборы кода; незакрытый забор — громкая ошибка,
а не тихая порча разбора. Вебхук игнорирует события под-задач (их жизнью управляет шаг).

## Как проверить

Тесты блоков Issue (порча тела и вложенные маркеры — громкая ошибка), разбора плана,
сборки постановки из каталога.

## Уроки

Трекер — не архив находок: у находок своя секция; git-каталог снимает потолки символов,
потому что контекст версионируется, а не пересобирается.
