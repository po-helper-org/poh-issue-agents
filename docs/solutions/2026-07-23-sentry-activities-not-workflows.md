# Sentry только из активностей — сетевой вызов из воркфлоу ломает реплей

## Ситуация

Пойманные сбои (триаж → `advisor:error`, `/estimate` → реакция «запутался») оставались
строками в логах контейнера; нужны адресуемые события с тегами service/repo/issue/stage.

## Причина

Тело воркфлоу детерминировано: сетевой вызов (отправка в Sentry) из воркфлоу-кода дал бы
расхождение при воспроизведении истории. Кроме того, без разворота первопричины все сбои
активностей схлопываются в один тип исключения.

## Решение

Sentry зовётся только из entrypoint-ов (`worker.py`, `webhook/main.py`) и из активностей —
никогда из воркфлоу. `_failure_reason()` разворачивает `.cause` `ActivityError` до
первопричины. Fingerprints: `[pipeline_failure, exc_type]` и `[estimate_failure, stage]`.
Скраббер вырезает ключ провайдера модели, GitHub-токен и подпись вебхука до отправки;
тела вебхуков не уходят. `configure()` идемпотентна и no-op без `SENTRY_DSN` — полный
откат снятием переменной и рестартом.

## Как проверить

Юнит-тесты скраббера, no-op без DSN, проброса reason и тегов; SDK ставится при сборке
образа (`docker compose up -d --build`), обычный рестарт его не подтянет.

## Уроки

Вся внешняя сторона Temporal-воркфлоу — в активностях; первопричину достают из
`ActivityError.cause`, иначе журнал ошибок неразличим.
