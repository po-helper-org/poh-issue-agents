# Словарь меток — один писатель и имена, выводимые из команд

## Ситуация

Управление контуром из мобильного приложения GitHub требует меток-триггеров (два тапа,
без ввода текста). Параллельно внедряется протокол взаимодействия агентов
(`needs-human:*`, `origin:agent`), и число семейств меток растёт — без правил имена
начинали бы расходиться, как уже разошлись триггерные.

## Причина

Метки живут в трёх ролях — триггер, состояние, протокол; каждое новое семейство изобретает
свои имена, и каталог в репозиториях отстаёт от кода.

## Решение

Команды объявлены один раз в `shared/commands.py`, имена меток `run:*` / `done:*` /
`failed:*` выводятся из них автоматически (тест пиннит соответствие). Петля исключена
структурно: запускает только `run:*`, метки исхода агент ставит себе сам — фильтр по
отправителю не нужен. Протокольные метки общего словаря (`shared/labels.py`) подчиняются
правилу «одна метка — один писатель»; внутренние (`advisor:*`, `priority:*`) остаются у
сервиса. Сокращённый триаж для `origin:agent`; рубильник `agents:off` проверяется до
первого обращения к модели. Позже (PR 136) три семейства меток сведены в единый каталог
вручную, с `ensure_labels_exist` и bootstrap-скриптом.

## Как проверить

Тесты соответствия команда-метка и словаря; bootstrap-скрипт приводит репозиторий к каталогу.

## Уроки

Имена меток выводят из одного источника правды; метка исхода никогда не совпадает с
триггером — петля исключается структурой, а не фильтром.
