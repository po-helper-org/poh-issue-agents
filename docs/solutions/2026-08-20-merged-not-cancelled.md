# Влитый PR — фаза merged, а не cancelled

## Ситуация

Любое закрытие Issue уводило цикл в `cancelled`: задача, доведённая до `main`, и снятая
руками оказывались в одном состоянии — «сколько дошло до main» по меткам не считалось.
Найдено живым прогоном: задача прошла путь целиком, PR влит, GitHub закрыл Issue по
`Closes #N` — контур поставил `phase:cancelled`.

## Причина

Фаза `merged` не использовалась нигде: ветка закрытия не спрашивала GitHub, влит ли PR.
Вторая итерация (PR 310): из `pr-open` хода в `merged` в таблице переходов не было —
спрашивать стали только из `pr-review`, а туда цикл попадает лишь по докладу внешнего
ревьюера; без доклада доведённая до main задача снова записывалась отменённой.

## Решение

Признак влитости берётся у самого PR (`pr_is_merged`), а не из причины закрытия:
`state_reason` одинаков у закрытия по `Closes` и руками «как выполненное», а доставки
событий закрытия Issue и PR идут наперегонки — ждать вторую, чтобы истолковать первую,
значит завести гонку. Ход `pr-open → merged` добавлен в таблицу с инициатором `external`:
таблица объявлена единственным источником правды, путь, которого в ней нет, а в жизни есть, —
второй невидимый источник. Из `merged` цикл не завершается (не терминальна: за ней testing
и released), закрытый Issue паркуется.

## Как проверить

Тесты `test_workflow_closed_by_merge`; влитый PR ставит `phase:merged` из обеих фаз.

## Уроки

Успех и отмену различают по факту от источника (влит ли PR), а не по событию закрытия;
новый путь добавляют в таблицу переходов, а не обходом проверки.
