# Git-механика публикации — общая для провайдеров, инциденты записаны в код

## Ситуация

Стадия разработки на GitLab-репозитории падала «клиент не умеет publish_worktree»:
диспетчер провайдеров резолвит метод по репозиторию, а метода у GitLab-клиента не было.
Проверка равенства веток падала наMR-нумерации.

## Причина

Git-механика коммита и пуша была написана внутри GitHub-клиента; второй провайдер означало
бы вторую копию — следующая правка дошла бы до одного и не дошла бы до второго.

## Решение

`worker/worktree.py` — git-механика, общая для обоих провайдеров; в ней прямо записаны
разборы прошлых инцидентов: пустой индекс при ретрае существующей ветки, игнор-лист
целевого репозитория против списка принудительно включаемых путей, проверка присутствия
путей фактом. Провайдерное — только имя пользователя для credential-хелпера, почта
коммиттера и способ открыть PR/MR. Попутно исправлен сторож выкладки: отказ подключения
и отказ реплея перестали путаться в одном перехватчике.

## Как проверить

Тесты публикации в GitLab (PR/MR создаются общей механикой); прогон разработки
на GitLab-репозитории доходит до MR.

## Уроки

Общий код — рядом с записанными в нём прошлыми инцидентами; копия механики для второго
провайдера — отложенный отказ.
