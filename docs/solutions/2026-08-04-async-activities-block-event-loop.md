# Блокирующие вызовы в async-активностях морозили общий event loop

## Ситуация

Два симптома с одной причиной. (1) Прогон триажа по всему бэклогу шёл на порядок
медленнее ожидаемого. (2) Стадия FNR падала по heartbeat-таймауту: 6,5 минуты без
сердцебиения при лимите 300 с, ретрая нет (`maximumAttempts=1`).

## Причина

Воркер крутит один общий asyncio-цикл на все `async def`-активности. Часть активностей
звала блокирующий `requests` клиента GitHub (timeout=30) прямо в корутине. Один такой
вызов по одному Issue замораживал цикл целиком — включая heartbeat чужой длинной
активности, работающей параллельно.

## Решение

В PR 11 тяжёлые активности переведены из `async def` в синхронные `def` (Temporal сам
разводит их по потокам) плюс `ThreadPoolExecutor(3)`. В PR 24 оставшиеся async-активности
(`mark_analyzing`, `ack_command`, `publish_analysis_error`) обёрнуты в `asyncio.to_thread` —
тот же паттерн, что уже применялся в длинных пайплайнах.

## Как проверить

AST-скан: внутри `async def`-активностей нет прямых вызовов `github_client.*`;
параллельные `/analyze` по разным Issue не срывают heartbeat друг другу.

## Уроки

В temporalio блокирующий I/O — синхронные активности или `to_thread`. Сердцебиение убивает
не своя активность, а соседняя, заморозившая общий цикл.
