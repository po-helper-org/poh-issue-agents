# Эпизод пишется даже при падении прогона, тесты — файлом вне дерева

## Ситуация

Три дыры одной темы. (1) Результат тестов измерялся в момент прогона и выбрасывался —
в восстановлении постфактум «неизвестно» навсегда; вердикт судьи считался по четырём
сигналам из десяти. (2) Запись об итерации стояла после успешных шагов: красные тесты
и сорвавшийся прогон записей не оставляли — слой собирал статистику только по удачам
и на них же учился. (3) Файл намерений удалялся как «служебный» за четыре секунды до
чтения. (4) Правка в две строки на задачу «описать поведение функций» получила оценку 0.93
без замечаний: в записи об итерации не было текста задачи, судья не мог сказать ничего
о соразмерности — reward hacking при внешне хороших числах.

## Причина

Исход тестов не переживал шаг; запись эпизода стояла не в `finally`; «снять из рабочего
дерева» и «уничтожить» были спутаны; запись не несла постановку.

## Решение

Исход тестов пишется файлом в корень задачи — вне рабочего дерева git (в коммит не
попадёт) и вне payload Temporal; пишется до возможного исключения — красный прогон самый
интересный для разбора; пропуск записывается как неизвестно, а не успех (пустая команда
тестов иначе засчиталась бы зелёным). Запись эпизода перенесена в `finally` под отдельным
`workflow.patched`. Файлы из перечня сохраняемых перекладываются в корень задачи вне
рабочего дерева: обязан исчезнуть из клона до коммита, содержимое нужно после. Заголовок
и начало тела задачи (предел на стороне отправителя) едут в записи; пустое тело едет
как отсутствующее, а не пустая строка.

## Как проверить

Тесты интеграции памяти; живой сорванный прогон оставляет запись с исходом тестов.

## Уроки

Обучающий слой обязан видеть неудачи — иначе он оптимизирует выживание, а не качество;
сигнал, восстанавливаемый только в момент события, пишется в момент события.
