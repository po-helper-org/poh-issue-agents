# main красный на 15 тестах — два живых краш-лупа после трёх PR подряд

## Ситуация

`main` красный с момента мержа PR 108: 15 упавших тестов, унаследованных всеми
последующими PR. Разбор показал не «протухшие фикстуры», а реальные баги.

## Причина

(1) Таблица переходов не знала связку `system-requirements → in-development/pr-open`
из быстрого пути автостарта — `InvalidTransition`, воркфлоу навсегда в краш-лупе на каждой
попытке; оба флага автостарта были включены на стенде, баг живой. (2) Таблица не знала
выход из `DUPLICATE` сразу в анализ/разработку (PR 105). (3) Активность `read_issue_labels`
вызывалась из воркфлоу, но не была зарегистрирована в воркере — первый вызов на проде упал
бы `NotFoundError`. (4) Guard рабочего каталога БФТ проверял конкатенацию полей, а не
каждое поле.

## Решение

Все четыре места закрыты; тесты дефектов (не фикстур) перечинены. Отдельно: три PR
(102, 105, 108) мержились подряд с красным CI у каждого — поэтому трещины сложились.

## Как проверить

CI зелёный; быстрые пути автостарта и выхода из дубля проходят по таблице переходов;
тест проводки воркера ловит незарегистрированную активность.

## Уроки

Красный `main` — не фон, а накопитель: каждый следующий PR наследует трещины и добавляет
свои; новый путь обязан попадать в таблицу переходов и в список регистрации одновременно
с кодом, который его зовёт.
