# Релиз-менеджер подключается модулем на своей очереди

## Ситуация

Контур заканчивался мержем PR; релиз (мерж, выкатка, проверки живого сервиса) делался
руками. Агент релиза живёт в соседнем репозитории — его надо подключить, не связывая
репозитории.

## Причина

Шаг релиза держит активность минутами; на общем пуле из трёх слотов он вытеснял бы
триаж Issue. Несобравшийся модуль-сосед не имеет права останавливать обработку Issue.

## Решение

Пакет с пином на полный SHA в requirements воркера; мост `worker/delivery_bridge.py` —
точка подключения (токен App, активность разрешения конфликтов); второй воркер на очереди
`delivery`. Команда `/release` и метка `run:release`; идентификатор релиза — по репозиторию,
а не по Issue: два одновременных релиза мержили бы в одну ветку по двум планам; повторная
команда упирается в «уже стартован» — это и есть защита. Нет пакета — воркер стартует без
релизов, а не падает. Круг ревью на стороне контура: вердикт ревьюера — гейт мержа;
исчерпаны три круга при тех же замечаниях — метка «нужен человек», PR не отгружается.

## Как проверить

Живые релизы на демо-репозитории (четыре подряд: мерж, ожидание мержабельности после
соседа, откат по метрике); ревью-гейт блокирует мерж без вердикта.

## Уроки

Дорогие соседние роли — своя очередь Temporal и пин SHA; интеграционный модуль падает
мягко: его отсутствие выключает функцию, а не сервис.
