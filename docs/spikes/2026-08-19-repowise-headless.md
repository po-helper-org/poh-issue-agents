# Спайк: Repowise в headless-среде — учётная запись, сеть, провайдер модели

> **Дата:** 19.08.2026
> **Требование:** FR-1 из `sa_documentation/FNR/FNR_5/system_requirements.md` (блокирующее)
> **Задачи:** po-helper-org/poh-infra#1, po-helper-org/poh-issue-agents#72
> **Итог:** вердикт дебатов остаётся в силе; концепт A реализуем; четыре поправки к спеке

---

## Вопрос

Спека FNR-5 стоит на допущении: пакет `repowise` работоспособен без облачной учётной записи. Допущение не проверено, а команды `login`, `logout`, `whoami` в CLI присутствуют. Отрицательный результат отменял вердикт дебатов и возвращал выбор к концептам C, D, E.

Дополнительно проверялось: принимает ли пакет ключ z.ai как провайдер модели и чем он эмбеддит.

## Стенд

Тестовый репозиторий — копия `po-helper-org/poh-demo-checkout` (14 файлов, история git на месте), смонтированная в контейнер. Образ собран для спайка:

```dockerfile
FROM python:3.11-slim
RUN apt-get update && apt-get install -y --no-install-recommends git curl \
    && rm -rf /var/lib/apt/lists/*
RUN pip install --no-cache-dir repowise==0.44.0
RUN git config --system --add safe.directory '*'
WORKDIR /workspace
```

## Результат

### 1. Учётная запись НЕ требуется — допущение подтверждено

`repowise doctor` при неавторизованном состоянии:

```
Hosted account        OK      Not signed in (optional: repowise login)
Providers             OK      anthropic, codex_cli, deepseek, gemini, kimi,
                              litellm, mock, ollama, openai, opencode, openrouter
```

Выполнены без `repowise login`, все успешно:

| Команда | Результат |
|---------|-----------|
| `repowise init --no-prose -y` | 12 файлов, 8 символов, 11 страниц вики, граф 35 узлов / 33 ребра, git-история по 3 файлам, 5.5 с |
| `repowise mcp --transport streamable-http` | сервер поднялся, рукопожатие `initialize` прошло |
| `repowise serve --no-ui` | API поднялся, `/health` отвечает `{"status":"healthy","db":"ok"}` |
| `repowise generate --unwritten` | 3 страницы написаны моделью |

Сам сервер MCP в поле `instructions` сообщает про `repowise init --yes`: «it needs no API key».

**Вывод: вердикт дебатов остаётся в силе, концепт A реализуем.**

### 2. `git` в образе отсутствует — обязателен

Базовый `python:3.11-slim` не несёт `git`, а действующий `../poh-infra/mcp/poh-org/images/Dockerfile.repowise` ставит только пакет. В таком контейнере `repowise doctor` даёт `Git repository FAIL — Not a git repo`, то есть история и blame — половина ценности индекса — недоступны.

Дополнительно нужен `git config --system --add safe.directory '*'`: контейнер работает от root, смонтированные клоны принадлежат другому пользователю, и без этого git отказывается их читать.

Требование FR-2 уже предписывает собрать образ с `git`. Спайк подтверждает, что это не удобство, а условие работоспособности.

### 3. `repowise mcp` слушает только loopback — нужна версия 0.44.0

В версии `0.36.0` (та, что стоит в действующем образе организации) у `repowise mcp` нет флага `--host`:

```
INFO:     Uvicorn running on http://127.0.0.1:7338
```

Порт опубликован наружу, но обращение с хоста не проходит:

```
с хоста:              HTTP 000 (соединение не установлено)
изнутри контейнера:   HTTP 406 (валидный ответ MCP)
```

Для схемы с отдельным контейнером прокси это блокирующий дефект: эндпоинт недостижим по сети.

В версии `0.44.0` флаг появился:

```
--host TEXT   Host to bind for HTTP/SSE transports. Defaults to the
              REPOWISE_HOST environment variable, or 127.0.0.1.
              Use 0.0.0.0 to ...
```

С `--host 0.0.0.0` эндпоинт доступен снаружи, рукопожатие проходит:

```json
{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2024-11-05",
 "serverInfo":{"name":"repowise","version":"1.29.0"}, ...}}
```

**Вывод: нижняя граница версии — `0.44.0`.** Действующий образ организации отстал на восемь минорных версий.

### 4. Коллизия имени `REPOWISE_HOST`

Пакет читает `REPOWISE_HOST` как **адрес привязки** сокета. Спека (FR-8) использует это же имя для **публичного домена веб-админки**. Домен, положенный в эту переменную, заставит `repowise mcp` пытаться слушать на нём.

**Вывод: переменную публичного домена переименовать.**

### 5. `repowise serve` несёт собственный guard

При привязке к не-loopback адресу без ключа API отвечает `403` с явным объяснением:

```json
{"detail":"Server is reachable from the network but REPOWISE_API_KEY is not set.
           Set REPOWISE_API_KEY or bind to 127.0.0.1."}
```

С заданным `REPOWISE_API_KEY` обращение без заголовка даёт `401`, с `Authorization: Bearer <ключ>` — `200` и данные. Точка `/health` открыта в обоих случаях и ключа не требует.

**Вывод:** у веб-админки два слоя доступа, а не один. Требование FR-8 дополняется ключом API; `/health` пригоден для проверки живости без учётных данных.

### 6. z.ai принят как провайдер модели

```
Provider: openai / glm-4.6
Generated 3 pages in 251.5s — every page is now written.
```

Переменные — `OPENAI_API_KEY` и `OPENAI_BASE_URL`, выведенные из `ZAI_API_KEY` и `ZAI_BASE_URL`, тем же приёмом, что применяется в `worker/activities.py:762` для `claude -p`.

Скорость: 251.5 с на 6 страниц по репозиторию из 14 файлов. На репозиториях контура это часы, а не минуты, — генерацию прозы планировать отдельным долгим шагом.

### 7. Эмбеддинги z.ai НЕ работает — риск R-6 подтверждён

Эмбеддер выбирается автоматически как `openai`, то есть уходит на тот же адрес z.ai, и каждый вызов отвергается:

```
Warning: failed to embed file_page:src/server.mjs: Error code: 400 -
  {'error': {'code': '1211', 'message': 'Unknown Model, please check the model code.'}}
Done! Indexed 0 items (6 failed) -> /workspace/.repowise/lancedb
```

Векторный индекс пуст. Полнотекстовый поиск при этом работает — `repowise init` прямо сообщает: «Full-text search works now; semantic search needs an embedder (Ollama is the keyless one)».

**Вывод:** семантический поиск по индексу через z.ai недоступен. Варианты: поднять Ollama рядом (эмбеддер без ключа), взять отдельный ключ у провайдера с эмбеддингами, либо принять деградацию до полнотекстового поиска. Решение требуется до FR-4.

## Поправки к спеке

| | Что | Затрагивает |
|---|---|---|
| П-1 | Нижняя граница версии `repowise` — `0.44.0`; зафиксировать точной версией, а не диапазоном | FR-2 |
| П-2 | `repowise mcp` запускать с `--host 0.0.0.0`; в образ ставить `git` и `safe.directory` | FR-2, FR-6 |
| П-3 | Переменную публичного домена переименовать из `REPOWISE_HOST` — имя занято пакетом под адрес привязки | FR-8 |
| П-4 | Веб-админке добавить `REPOWISE_API_KEY`; `/health` использовать для проверки живости без учётных данных | FR-8 |
| П-5 | Выбрать эмбеддер до FR-4: Ollama, сторонний ключ либо осознанная деградация до полнотекстового поиска | FR-4, R-6 |

## Что осталось непроверенным

- Режим workspace на нескольких репозиториях (проверялся один).
- Одновременная запись индексатора и чтение эндпоинтов (риск R-3).
- Формат конфигурации MCP у агента разработки (требование FR-16, отдельный спайк).
