# Спайк: формат конфигурации MCP у агента разработки (OpenHands)

> **Дата:** 19.08.2026
> **Требование:** FR-16 из `sa_documentation/FNR/FNR_5/system_requirements.md`
> **Задача:** po-helper-org/poh-issue-agents#72
> **Итог:** поддержка есть, транспорт `http` с заголовком — раздел 4.3 спеки реализуем

---

## Вопрос

Требования FR-17 — FR-19 стоят на допущении, что версия агента разработки, зафиксированная в `openhands/Dockerfile`, принимает описание внешнего MCP-сервера по HTTP и умеет передавать токен. Допущение относится к стороннему компоненту и не проверялось.

## Стенд

Собранный образ `poh-openhands-runner:local`, пакет `openhands` версии `1.16.0` (пин в `openhands/Dockerfile`).

## Результат

### 1. Поддержка есть, транспорт HTTP с заголовком

У CLI есть подкоманда `mcp` с полным набором операций:

```
openhands mcp {add,list,get,remove,enable,disable}
```

Параметры `add`, релевантные требованию:

```
--transport {http,sse,stdio}   Transport type for the MCP server
--header HEADER                HTTP header for http/sse transports
                               (format: 'key: value')
--enabled / --disabled         Состояние сразу после добавления
```

Команда под наш случай:

```bash
openhands mcp add repowise --transport http \
  --header "Authorization: Bearer <токен>" \
  http://<прокси>:<порт>/mcp
```

**Вывод: раздел 4.3 спеки реализуем, обходных путей не требуется.**

### 2. Конфигурация лежит в домашнем каталоге пользователя, а не в каталоге задачи

Файл: `/home/agent/.openhands/mcp.json` — домашний каталог пользователя `agent` (uid 10001, заведён в `openhands/Dockerfile`).

Формат:

```json
{
  "mcpServers": {
    "repowise": {
      "url": "http://<прокси>:<порт>/mcp",
      "transport": "http",
      "headers": {
        "Authorization": "Bearer <токен>"
      },
      "auth": null,
      "sse_read_timeout": null,
      "timeout": null,
      "description": null,
      "icon": null,
      "authentication": null,
      "enabled": true
    }
  }
}
```

**Следствие для FR-17.** Воркер готовит каталог задачи в общем томе, но домашний каталог раннера в этот том не входит и живёт внутри одноразового контейнера. Значит конфигурацию нельзя просто положить рядом с постановкой — её надо либо создать внутри контейнера перед запуском агента, либо смонтировать в `/home/agent/.openhands/`.

Из двух вариантов предпочтительнее монтирование файла: команда `mcp add` потребовала бы обёртки вокруг `ENTRYPOINT`, а он сейчас задан одной строкой и запускает агента напрямую.

**Токен в файле.** `mcp.json` содержит токен открытым текстом внутри контейнера. Контейнер одноразовый и умирает вместе с задачей, но требование FR-17 «токен не попадает в текст постановки» этим не отменяется: постановка публикуется артефактом, а `mcp.json` — нет.

## Что осталось непроверенным

- Поведение агента при недоступном MCP-сервере: деградирует ли он к работе без индекса или падает на старте. Проверяется при реализации FR-17 вместе с ветвью деградации FR-14.
- Попадают ли обращения к MCP в собственный журнал событий агента — на артефакт это не влияет (его собирает прокси, FR-18), но полезно для разбора прогонов.
