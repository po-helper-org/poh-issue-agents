# Issue #107: Исследование - Краткое резюме

## Суть исследования

Задача: Провести БФТ + системный анализ и определить архитектуру для централизованного репозитория стандартов написания кода для AI-агентов.

## Ключевые находки

### 1. Проблема реальна и уже проявляется
- **Проблема:** Разные агенты импровизируют стандарты по-своему
- **Доказательство:** PR #97/#105 — обход декларативных паттернов хардкодом вместо каноничного источника истины
- **Последствие:** Архитектурная непоследовательность между репозиториями

### 2. Система уже содержит зачатки решения
- `AGENTS.md` — правила репозитория (но дублируются)
- `.claude/skills/` — 21+ скилл с пересекающимися паттернами
- Существующие механизмы доставки контекста (volumes, Docker)
- Всё это не систематизировано и не вынесено в отдельный репозиторий

### 3. Техническое решение существует и проверено
**Рекомендуемая архитектура:**

| Компонент | Решение | Обоснование |
|-----------|---------|-------------|
| **Механизм подключения** | Git Submodule + CI-проверка | Детерминизм версии + независимый релизный цикл |
| **Локальные расширения** | `.standards.overrides/` + `.standards-config.toml` | Гибкость + явность конфликтов |
| **Подключение к агентам** | Инъекция в промпт → MCP-сервер | Пошаговый подход: от простого к сложному |
| **Валидация контента** | Автоматическая (LLM) + Human review | Качество + масштабируемость |
| **Формат файлов** | Markdown + Frontmatter | Человекочитаемость + машинная обработка |

## Рекомендуемая архитектура

```
poh-coding-standards (отдельный репозиторий)
├── universal/           # Универсальные правила
│   ├── architecture/
│   ├── security/
│   └── testing/
├── python/              # Язык-специфичные
├── javascript/
└── go/

↓ git submodule (фиксированный commit)

Репозиторий-потребитель
├── .standards/          # Submodule
├── .standards.overrides/ # Локальные расширения
└── .standards-config.toml # Конфигурация

↓ HTTP/MCP

MCP-сервер (опционально для продакшена)
├── search (vector search)
├── get (file retrieval)
└── validate (LLM checks)
```

## План внедрения

### Этап 1: MVP (2-3 недели)
- Создать репозиторий `poh-coding-standards`
- Мигрировать существующие правила
- Подключить к одному пилотному репозиторию
- Базовая загрузка через файлы + инъекция в промпт

### Этап 2: Production (1-2 месяца)
- Разработать MCP-сервер с поиском
- Внедрить механизм валидации
- Мигрировать ключевые репозитории

### Этап 3: Масштабирование (3+ месяца)
- Собирать и анализировать метрики
- Постоянно улучшать правила
- Расширить покрытие на все репозитории

## Ключевые преимущества

1. **Единообразие кода** — одни и те же правила во всех репозиториях
2. **Независимость релизных циклов** — стандарты обновляются отдельно от сервисов
3. **Версионная детерминированность** — агенты видят ту же версию, что и разработчики
4. **Гибкость** — возможность локальных расширений под конкретный репозиторий
5. **Качество** — систематическая валидация правил

## Риски и митигация

| Риск | Митигация |
|------|-----------|
| Недетерминизм версий | Фиксация commit hash + CI-проверка |
| Сложность MCP-сервера | Постепенное внедрение, начиная с файлов |
| Противоречия в правилах | Автоматическая валидация + human review |
| Сопротивление изменениям | Постепенное внедрение + обучение |

## Метрики успеха

1. **Покрытие:** % репозиториев, использующих стандарты
2. **Качество:** % правил, прошедших валидацию с первого раза
3. **Использование:** Количество запросов к MCP-серверу
4. **Удовлетворённость:** Опросы разработчиков
5. **Снижение noise** в code review (одни и те же замечания)

## Заключение

**Централизованный репозиторий стандартов — необходимый компонент инфраструктуры** для организации, где активно используются AI-агенты. Техническое решение проверено, организационный процесс понятен.

**Рекомендация:** Начать с простого (файлы + инъекция в промпт), постепенно усложняя до полноценного MCP-сервера.
