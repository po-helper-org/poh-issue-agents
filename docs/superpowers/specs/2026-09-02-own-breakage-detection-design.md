# Разработка отличает свою поломку от чужой

Дата: 2026-09-02
Состояние: замысел согласован, к реализации

## Откуда задача

Два живых прогона разработки подряд, оба 2 сентября 2026, оба на
`po-helper-org/poh-demo-checkout`:

- `#166` — агент отработал тринадцать минут, `dev_tests` упал, работа исчезла;
- `#167` — то же самое, но работа спаслась черновиком (`#295`, уже смержено).

**В обоих случаях тесты были красными ДО агента.** `main` демо-репозитория
падает тремя тестами с 1 сентября: промокод `SUMMER20` имеет
`activeUntil: '2026-09-01'` (`src/pricing.mjs:23`), `validatePromoCode`
отсекает его по текущей дате (`:82`). Агент не сломал ничего — он просто не
смог доказать обратное.

`_dev_tests` (`worker/activities.py:3252`) гоняет `DEVELOP_TEST_COMMAND` и
бросает `RuntimeError` на любом ненулевом коде возврата. Различать «я сломал»
и «было сломано до меня» ему нечем: кроме кода возврата, у него нет ничего.

Следствие — контур не замыкается. Каждый прогон разработки заканчивается
человеком независимо от того, годный код написал агент или нет.

## Что решаем

Прогон разработки объявляет отказ только за **свои** поломки.

Признак «своя поломка» — не вид отказа и не код возврата, а разница множеств:
тесты, упавшие после правки агента, минус тесты, упавшие до неё.

## Как выглядит

`#167` при работающем механизме:

- перед агентом снимается базовая линия: три промо-теста уже красные;
- агент правит `src/server.mjs`, `dev_tests` даёт те же три падения;
- разница пуста — **прогон удался**, открывается обычный PR;
- в теле PR и в комментарии строка: эти три теста падали до правки, агент их
  не трогал.

Если бы агент сломал четвёртый — отказ, и в причине стоял бы **только он**, без
трёх чужих.

## Требования

### Базовая линия

**B1.** Базовая линия снимается **отдельной активностью** между `dev_prepare`
и `dev_run_agent`: свой шаг в Temporal, свой таймаут, свои ретраи. Внутри
`dev_prepare` её быть не должно — там она делит таймаут с клонированием и
невидима в истории прогона.

**B2.** Базовый прогон **не бросает исключение на красных тестах**. Красная
база — факт о репозитории, а не отказ разработки. Исход возвращается значением.

**B3.** Исход прогона тестов — это множество имён упавших тестов плюс признак
«исход разобран». Кода возврата недостаточно: он не отличает размен (агент
починил один тест и сломал другой) от чистой работы.

### Откуда берутся имена

**B4.** Имена читаются из отчёта **JUnit XML**, а не из текста вывода.

Разбор stdout привязал бы механизм к двум-трём знакомым раннерам, а JUnit XML
умеют почти все: Maven и Gradle пишут его сами без флагов
(`target/surefire-reports/*.xml`, `build/test-results/**/*.xml`), pytest — по
`--junit-xml`, `node --test` — по `--test-reporter=junit` (проверено фактом
2026-09-02 на Node 26 и pytest), PHPUnit — по `--log-junit`.

**B5.** Отчёт ищется по набору обычных путей, переопределяемому переменной
окружения на репозиторий. Для Maven и Gradle настройка не нужна вовсе.

**B6.** Упавшим считается `<testcase>` с вложенным `<failure>` или `<error>`.
Имя теста собирается из `classname` и `name`: одного `name` мало, одинаковые
имена в разных наборах — обычное дело.

### Решение по исходу

**B7.** Свои поломки = упавшие после − упавшие до.

**B8.** Свои поломки есть — **отказ**, как сегодня. В тексте причины
перечислены **только свои**: чужие падения в него не идут. Иначе человек
читает список из четырёх поломок, из которых три к задаче не относятся.

**B9.** Своих поломок нет, чужие есть — **прогон удался**. PR открывается
обычным, не черновым. В теле PR и в комментарии называется прямо: эти N тестов
падали до правки, агент их не трогал.

**B10.** Не упало ничего — поведение сегодняшнее.

### Осторожность там, где не знаем

**B11.** Исход **не разобран** — отчёта нет, он битый, или тестов в нём ноль —
контур ведёт себя **как сегодня**: любой ненулевой код возврата считается
отказом.

Это касается обоих концов: неразобранная база означает, что послабления не
будет, даже если после агента отчёт разобрался.

Молчаливое послабление опаснее лишнего отказа: контур, переставший замечать
поломки из-за сбоя собственного разбора, хуже контура, который зря беспокоит
человека. Незнакомый стек ничего не ломает — он просто не получает послабления,
пока в нём не настроят отчёт.

**B12.** Базовый прогон, упавший по таймауту или отказу окружения, — не отказ
стадии. Исход считается неразобранным (B11), разработка продолжается.

**B13.** Тест, переименованный агентом, считается **своим**: старое имя из
базовой линии исчезло, новое красное. Агент его тронул — он за него и отвечает.

**B14.** Пустой `DEVELOP_TEST_COMMAND` — шага нет вовсе, ни базового, ни
итогового, как сегодня.

### Сигналы слою саморефлексии

**B15.** Сигнал `tests_passed` (`_write_signal`, `worker/activities.py:2975`)
отражает **свои** поломки, а не общую красноту. Иначе слой учится на шуме:
прогон с чистой работой в красном репозитории засчитывался бы как неудача.

**B16.** Факт чужой красноты пишется **отдельным** сигналом. Слить его в
`tests_passed` значит потерять различие ровно там, где оно и заводится.

### Прогон и его история

**B17.** Новая активность и новая ветка решения требуют `workflow.patched`.
Гвард `tests/test_workflow_replay.py` обязан остаться зелёным.

**B18.** Частичная выкладка (`dev_publish_partial`, смержена 2026-09-02) не
меняется: отказ по своим поломкам после агента по-прежнему даёт черновой PR.

## Пограничные случаи

| Случай | Поведение |
|---|---|
| База красная, после агента те же падения | Успех, обычный PR с оговоркой (B9) |
| База красная, после агента добавилось падение | Отказ, в причине только новое (B8) |
| База красная, агент починил её часть | Успех: своих поломок нет (B7) |
| Размен: починил один, сломал другой | Отказ — счёт тот же, множества разные (B3) |
| База зелёная, после агента красно | Отказ, как сегодня |
| Отчёта нет ни до, ни после | Сегодняшнее поведение (B11) |
| Отчёт есть после, но не было до | Сегодняшнее поведение (B11) |
| Базовый прогон упал по таймауту | Не отказ; исход неразобран (B12) |
| Агент переименовал тест | Падение считается своим (B13) |
| `DEVELOP_TEST_COMMAND` пуст | Шагов нет (B14) |
| Прогон разработки идёт с прежним кодом | Реплей не ломается (B17) |

## Чем проверяется

- Разбор JUnit XML на реальных образцах `pytest` и `node --test`.
- Своя поломка обнаружена; чужая пропущена; размен обнаружен.
- Причина отказа содержит только свои падения.
- Успех при чужой красноте даёт обычный PR и оговорку в его теле.
- Неразобранный отчёт даёт прежнее поведение на обоих концах.
- Отказ базового прогона не роняет разработку.
- Сигнал `tests_passed` отражает свои поломки; чужая краснота — отдельным
  сигналом.
- Гвард реплея зелёный; правка решений под маркером.

## Вне границ

- **Круг правок: агент чинит своё.** Следующая задача, и она строится на этой:
  без различения своего и чужого чинить нечего отличать.
- **Настройка отчёта в чужих репозиториях.** Механизм её поддерживает,
  проставление по репозиториям — работа эксплуатации.
- **Починка красноты `main` демо-репозитория.** Дата в тесте не зафиксирована
  (`tests/pricing.test.mjs`), но это задача самого демо-сервиса. Пока она не
  сделана, репозиторий остаётся полигоном для проверки поведения при срыве.
- **Прогон тестов на PR силами CI.** Отдельный давний блокер контура.
