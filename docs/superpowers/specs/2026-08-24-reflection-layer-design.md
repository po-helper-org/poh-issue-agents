# Слой саморефлексии контура: память самоулучшения на фазе Develop

Дата: 2026-08-24. Статус: дизайн согласован, реализация не начата.

## Задача

Контур доводит Issue до PR и на этом забывает всё. Каждый следующий прогон
начинается с нуля: те же ошибки, те же слепые зоны, те же потери времени.
Накопленное знание живёт в голове человека и в памяти сессий Claude Code —
контур им не пользуется.

Нужен слой, который после каждой итерации проработки ретроспективно разбирает
сделанное, оценивает результат по фактам, извлекает точку роста, кладёт её в
память и **проверяет на последующих прогонах, устранена ли причина**.

Образ результата — механизм самосовершенствования операционной эффективности и
качества решений, а не отчёт о проделанной работе.

Первый срез — **тонкий замкнутый цикл на одной фазе, Develop**. Вся цепь
целиком, но только для разработки: у неё самые объективные сигналы качества
(дифф, тесты, мерж, правки человека поверх, круги ревью). Issue и Delivery —
после того, как петля на Develop докажет себя.

## Главный риск и что ему противопоставляется

В контуре уже есть прецедент самооценки без заземления: вердикт стадии
`validate` в пайплайне БФТ пишет сама же модель (`#78`). Слой рефлексии,
построенный так же, произведёт красивые отчёты о росте и ноль роста.

Поэтому в дизайне три несущих ограничения:

1. **Оценка выводится из фактов контура**, а не из транскрипта. Транскрипт —
   вход для объяснения, не для вердикта.
2. **Каждое суждение модели несёт разрешимый якорь** — `file:line` в диффе, id
   комментария ревью или имя сигнала. Суждение без якоря отбрасывается
   детерминированным гейтом, не моделью.
3. **Урок не считается верным, пока не подтверждён последующими прогонами.**
   Статус `proposed` не даёт уроку влиять ни на что.

## Решения по открытым вопросам

Приняты владельцем 2026-08-24.

| Вопрос | Решение | Отвергнутая альтернатива и почему |
|---|---|---|
| Заземление оценки | Гибрид: объективные сигналы контура плюс LLM-судья с обязательной ссылкой на факт | Только сигналы — не покрывает «аналитика упустила требование», где чисел нет. Только LLM по транскрипту — повторяет историю `#78` |
| Обратный путь | Три канала: PR с правкой промптов, исполняемые гварды и тесты, retrieval уроков в постановку | Только отчёт человеку — узкое место в человеке, механизма самоулучшения не возникает |
| Момент рефлексии | Два такта: горячая запись сразу, холодный вердикт по созреванию сигналов | Один такт сразу — оценивает до появления фактов. Один такт по событию — намерения агента приходится реконструировать по артефактам, а это ~11% точности по TRAIL |
| Носитель памяти | Markdown в git как истина, запись в формате ACE-bullet, граф производный и отложенный | Graphiti с Neo4j/FalkorDB — на стенде 8 ГБ памяти и чужой прод рядом, плата без выгоды на объёме в сотни записей. БД у Temporal — теряется главное свойство: память как ревьюируемый дифф |
| Первый срез | Develop целиком, замкнуто | Леджер по трём фазам без уроков — месяц без проверки главной гипотезы. Ретроспектива по истории — нет горячих записей намерения |

## Что заимствуется

Ни один проект не берётся целиком. Берутся конкретные механизмы.

| Источник | Лицензия | Что берём |
|---|---|---|
| [ACE](https://arxiv.org/abs/2510.04618) (arXiv 2510.04618) | статья | Формат записи: playbook из пунктов со счётчиками helpful/harmful. Роли Generator / Reflector / Curator. Дельта-обновления ADD/UPDATE/REMOVE вместо перезаписи файла — защита от context collapse и brevity bias |
| [hermes-agent-self-evolution](https://github.com/NousResearch/hermes-agent-self-evolution) | MIT | Гейты на кандидата правки: тесты 100%, лимит размера, кэш-совместимость, семантическая верность цели, ревью человека. Правка едет PR'ом, прямой коммит запрещён |
| [GEPA](https://github.com/gepa-ai/gepa) | MIT | Рефлексия по полной трассе (ошибки, логи), а не по скаляру — Actionable Side Information. Интерфейс метрики: скаляр плюс диагностический лог. Парето-фронт кандидатов — во втором срезе, см. «Что не входит» |
| [Graphiti](https://github.com/getzep/graphiti) | Apache-2.0 | Модель: окно валидности у факта, противоречащий факт инвалидируется, а не удаляется; episodes как provenance для каждого вывода. Код не берём — берём модель |
| [iai-pme](https://github.com/CodeAbra/iai-personal-memory-engine) | MIT | Сырьё хранится дословно, без переписывания LLM. Разделение episodic / semantic / procedural. Консолидация фоном, decay неподкреплённого |
| [SKILL.nb](https://arxiv.org/abs/2606.08049) | статья | Жизненный цикл урока: promotion, demotion, retirement. Ablation-проверка «стало ли хуже без этого пункта» — против взаимных помех и распухания |
| [AgentFixer](https://arxiv.org/abs/2603.29848) | статья | Судье подаётся **пара трасс** — провальная и ближайшая успешная по той же зоне. У авторов перевес над анализом одиночной трассы в 46.2% случаев |
| [TRAIL](https://arxiv.org/html/2607.18754) | статья | Ограничение, а не приём: не поручать модели поиск виновного шага в длинной трассе. Атрибуцию сужаем структурой контура заранее |
| [Harness Engineering](https://lilianweng.github.io/posts/2026-07-04-harness/) (Weng, 2026) | статья | Файловая система как персистентная память. Перечень провалов: слабый оценщик, reward hacking, короткий горизонт |

[poh-memory-engine](../../../../poh-memory-engine) даёт готовый claim-слой поверх
markdown-frontmatter: `poh_memory/claims.py`, `supersede.py`,
`contradictions.py`, и гейт `sa_documentation/validate_ground.py` — образец
детерминированной отбраковки workslop. Битемпоральность получается без графа.

Отдельно проверен и отвергнут [nacre](https://github.com/nacre-work/nacre):
permission-aware слой контекста, ни памяти, ни рефлексии в нём нет.

## Единицы владения

| Единица | Где живёт | Ответственность |
|---|---|---|
| Репозиторий `poh-reflection` | `po-helper-org/poh-reflection` | память, библиотека рефлексии, гейты, CLI |
| `ReflectionWorkflow` | Temporal, id `reflect-<repo>-<issue>-<run_id>` | холодный такт: дождаться созревания, собрать сигналы, вынести вердикт, предложить уроки |
| Активность `capture_episode` | воркер `poh-issue-agents` | горячий такт: записать намерение до того, как оно забыто |
| Активность `inject_lessons` | воркер `poh-issue-agents` | подсыпать активные уроки в постановку и вернуть их id |
| CLI `poh-reflect` | `poh-reflection` | ручной прогон, пересчёт счётчиков, отчёт |

Память отдельным репозиторием, а не каталогом в `poh-issue-agents`: правки
промптов едут PR'ом **в** контур, а память живёт **вне** его истории. Иначе
каждая ретроспектива шумит в диффах основного репозитория и путается с
предметными изменениями.

## Структура `poh-reflection`

```
memory/
  episodes/<repo>/<issue>-develop-<run_id>.md   # сырьё, дословно
  verdicts/<repo>/<issue>-develop-<run_id>.md   # холодный вердикт
  lessons/<slug>.md                             # пункты playbook
poh_reflection/
  signals.py      # сбор объективных сигналов (GitHub, Temporal, Sentry, git)
  episode.py      # запись и чтение горячих записей
  judge.py        # LLM-судья, пара трасс на вход
  anchors.py      # разрешение якорей суждений
  curator.py      # дельта ADD/UPDATE/REMOVE, формирование PR
  counters.py     # helpful/harmful, переходы статусов
  retrieval.py    # отбор активных уроков по scope и близости
gates/
  anchor_gate.py  # суждение без разрешимого якоря — отброс
  size_gate.py    # потолки на урок и на блок в постановке
  semantic_gate.py# правка промпта не меняет исходную цель стадии
tests/
```

## Модель памяти

### Episode — горячая запись

Сырьё. **Дословно, без переписывания моделью.** Переписал — потерял
возможность реконструировать, когда факты изменятся (принцип iai-pme).

Файл `memory/episodes/<repo>/<issue>-develop-<run_id>.md`, frontmatter:

```yaml
run_id: <temporal workflow run id>
repo: po-helper-org/poh-demo-checkout
issue: 42
phase: develop
started_at: 2026-08-24T10:00:00Z
finished_at: 2026-08-24T10:21:00Z
branch: openhands/issue-42
pr_number: 57            # null, если PR не открыт
model: <модель агента разработки>
intent: |                # что собирался сделать
assumptions: []          # принятые допущения
alternatives_rejected: []
uncertainty: []          # где сомневался
lessons_injected: []     # id уроков, подсыпанных в постановку
trace_ref: <путь к диалогу разработки>
```

`lessons_injected` — несущее поле, не украшение. Без него счётчики
helpful/harmful не с чем сопоставлять: невозможно отличить «урок сработал» от
«урок вообще не читали».

Тело файла — постановка дословно и диалог агента, как их собрали `_dev_prepare`
([worker/activities.py:1636](../../../worker/activities.py)) и
`_collect_dev_dialog` ([worker/activities.py:1888](../../../worker/activities.py)).

### Verdict — холодный вердикт

Файл `memory/verdicts/<repo>/<issue>-develop-<run_id>.md`:

```yaml
episode: <run_id>
matured_at: 2026-08-31T00:00:00Z
maturation: merged | closed_unmerged | timeout
score: 0.0..1.0          # свёртка сигналов, детерминированная
signals: {...}           # таблица ниже, дословно
findings:                # суждения судьи
  - text: |
    anchor: {kind: diff|review|signal, ref: "src/foo.py:42"}
    severity: blocking | degrading | cosmetic
proposed_lessons: []     # id, ушедшие в память со статусом proposed
```

### Lesson — пункт playbook

Файл `memory/lessons/<slug>.md`:

```yaml
id: L-0031
scope: {phase: develop, activity: trigger_openhands_resolver, repo: "*"}
text: |                  # одно правило, императив, без рассуждений
evidence: [<run_id>, ...]        # provenance: эпизоды, откуда выведен
helpful: 0
harmful: 0
status: proposed | active | confirmed | regressed | dormant | superseded | retired
verifying_since: null
superseded_by: null
valid_from: 2026-08-24
invalidated_at: null
interventions:
  - kind: prompt_pr | guard | test
    ref: https://github.com/po-helper-org/poh-issue-agents/pull/NNN
    merged_at: null
trigger_signal: <имя сигнала, по которому проверяется устранение>
```

`trigger_signal` обязателен: урок без сигнала, который можно проверить, не
принимается гейтом. Это отсекает уроки вида «быть внимательнее».

## Сигналы Develop

Слой 1, без LLM. Половина уже есть в коде.

| Сигнал | Источник | Что ловит |
|---|---|---|
| `pr_opened` | `_dev_publish` ([activities.py:1959](../../../worker/activities.py)) возвращает `int \| None` | молчаливый отказ: агент отработал, PR нет |
| `diff_empty` | git diff по PR | агент ушёл писать в `/tmp` и доложил успех |
| `diff_harness_junk` | git diff по PR | `.task.md`, `.verdict.md`, `.followups.md` уехали в коммит |
| `tests_result` | `_dev_tests` ([activities.py:1940](../../../worker/activities.py)) | тесты |
| `pr_merged` | `pr_is_merged` ([activities.py:2356](../../../worker/activities.py)) | доехало ли до `main` |
| `pr_closed_unmerged` | GitHub | работу выбросили |
| `fix_rounds` | счётчик `run_pr_fix_round` ([activities.py:2389](../../../worker/activities.py)) | сколько кругов правок понадобилось |
| `escalated` | `finish_pr_fixing(settled=False)` ([activities.py:2458](../../../worker/activities.py)) | круг не сошёлся, ушло человеку |
| `line_survival` | git blame по `main` через N дней | доля строк агента, доживших до `main` |
| `human_rewrite` | `git log` по файлам PR после merge, автор ≠ агент | человек переписал сделанное |
| `issue_reopened` | GitHub | задача вернулась |
| `followup_bug` | GitHub, ссылка на PR | породило новый баг |
| `sentry_new` | Sentry MCP, окно после merge по затронутым файлам | сломало прод |
| `activity_attempt` | Temporal `workflow describe` | `Attempt > 1` у долгой активности — уже беда |
| `phase_duration` | Temporal | время фазы против медианы |
| `heartbeat_lost` | Temporal | срыв по heartbeat |
| `review_stub` | текст ревью в PR | заглушка «Preparing review...» вместо `## PR Reviewer Guide` |

`score` — детерминированная свёртка этой таблицы в `[0, 1]`. Вместе с таблицей
она даёт скаляр плюс диагностический лог: ровно интерфейс, который требует GEPA,
и ровно то, чего транскрипт не даёт.

Веса задаются одним конфигурационным файлом в `poh-reflection` и подчиняются
трём требованиям:

1. `pr_merged` весит не более 0.5 — иначе тривиальный PR геймит всю оценку;
2. `line_survival`, `fix_rounds` и `human_rewrite` вместе весят не менее 0.3 —
   это то, что тривиальным PR не подделывается;
3. любой из `diff_empty`, `pr_opened == false`, `review_stub` обнуляет `score`
   независимо от прочих: это молчаливый отказ, а не плохой результат.

Конкретные значения весов — предмет плана реализации; перечисленные требования
проверяются тестом.

## Судья

Вход: горячая запись, дифф, текст ревью, таблица сигналов и — приём AgentFixer —
**ближайшая успешная запись по той же зоне** (совпадение по `scope`, близость по
затронутым файлам). Сравнение пары трасс, а не разбор одиночной провальной.

Выход: список суждений, каждое с якорем. Гейт `anchors.py` разрешает якорь
фактически: `file:line` обязан существовать в диффе, id комментария — в PR, имя
сигнала — в таблице. Неразрешимый якорь → суждение отброшено гейтом, не моделью.
Образец — `validate_ground.py` в poh-memory-engine.

Судья **не ищет виновный шаг в трассе**. Атрибуция сужена заранее структурой
контура: фаза, активность, артефакт. По TRAIL точность моделей на разметке
трасс ~11%, атрибуция до шага ~40% — на этом строить нельзя.

Модель судьи вызывается прямыми вызовами API, не через `claude -p`: один
процесс CLI — 356 МБ RSS, дороже всего контейнера воркера.

## Два такта

### Горячий

Активность `capture_episode` в конце `trigger_openhands_resolver`
([activities.py:2021](../../../worker/activities.py)), до возврата фазы.
Синхронно, дёшево, без LLM: пишет то, что уже известно коду.

Намерение, допущения и сомнения агент отдаёт файлом `.reflect.md` в рабочем
каталоге — так же, как сейчас отдаёт `.task.md`. Файл читается активностью и
уезжает в запись; в коммит не попадает, `.reflect.md` добавляется к списку
мусора контура рядом с `.task.md`, `.verdict.md`, `.followups.md`.

Чтобы файл появился, в постановку добавляется требование его написать — это
правка `_dev_prepare`, а не отдельный канал влияния. Если файла нет, эпизод
пишется без `intent`, `assumptions` и `uncertainty`: сигналы и дифф остаются, и
холодный такт работает по ним. Отсутствие файла — не срыв стадии, но оно
отмечается в вердикте флагом `intent_missing`.

### Холодный

Отдельный `ReflectionWorkflow`, а не фаза `IssueLifecycle`. Причина: цикл Issue
завершается раньше, чем созревают сигналы — `line_survival` и `sentry_new`
требуют дней.

```
capture_episode
   | старт дочернего прогона, detached
ReflectionWorkflow(run_id)
   | ждёт: pr_merged | pr_closed_unmerged | таймер 7 суток
collect_signals        # без LLM
   | score, таблица
judge_episode          # LLM, пара трасс
   | суждения с якорями
anchor_gate            # детерминированный отброс
propose_lessons        # дельта к playbook
   | статус proposed
publish_verdict        # файл в память, PR в poh-reflection
```

Политики ретраев, по правилам контура: `maximum_attempts=1` на `judge_episode`
(недетерминирована, стоит денег, повтор прогоняет работу заново — как на `#39`);
`maximum_attempts=3` на `collect_signals` (детерминирована, сетевая).

Результат каждой активности проверяется **по артефакту**, а не по коду возврата:
`judge_episode` без файла суждений — провал стадии, даже если процесс вышел
нулём.

Расписание: холодный такт гоняется в тихое окно, не параллельно с разработкой.
Причина — один ключ z.ai на всё, и он уже главный источник флаки.

## Обратный путь

### Канал 1 — retrieval в постановку

Активность `inject_lessons` перед `_dev_prepare`
([activities.py:1636](../../../worker/activities.py)). Отбирает уроки со
статусом `active` или `confirmed` по совпадению `scope` и близости к задаче,
добавляет в `parts` блок «Уроки контура» и возвращает список id.

Потолки: не более 15 пунктов, не более 2000 токенов. Превышение — отбрасываются
пункты с худшим отношением `helpful / (helpful + harmful)`.

Возвращённые id пишутся в `lessons_injected` эпизода. Без этого счётчики врут.

### Канал 2 — PR с правкой промптов

`curator.py` формирует **дельту**: ADD / UPDATE / REMOVE отдельных пунктов в
`prompts/system_*.md` или `AGENTS.md`. Не переписывание файла целиком — это
защита от context collapse, из-за которого наивная рефлексия стирает
накопленное, сжимая его.

Гейты перед открытием PR, по образцу hermes-agent-self-evolution:

1. полный прогон тестов `poh-issue-agents` зелёный;
2. `size_gate`: файл промпта не вырос больше чем на 15%;
3. `semantic_gate`: правка не меняет исходную цель стадии (проверка отдельным
   вызовом, с обязательной цитатой изменённого фрагмента);
4. кэш-совместимость: правка не попадает в середину закэшированного префикса;
5. мерж — только человеком.

### Канал 3 — гвард или тест

Формализуемый урок превращается в проверку в коде контура. Канал сильнее двух
других: не размывается и не зависит от того, прочитала ли модель контекст.

Существующие уроки контура почти все такие: «дифф пуст — провал стадии», «в
ревью нет `## PR Reviewer Guide` — провал», «владелец каталога задачи не 10001 —
стоп», «`Attempt > 1` у долгой активности — беда».

Гвард приезжает тем же PR, что и правка промпта, но живёт дольше: правка
промпта может быть вытеснена, гвард остаётся до явного удаления.

## Петля подтверждения

Урок с влитой интервенцией: `status: active`, `verifying_since: <merged_at>`.

Дальше — арифметика на объективных сигналах, без LLM. Каждый последующий эпизод,
где урок был в `lessons_injected` либо соответствующий гвард активен:

- `trigger_signal` не сработал → `helpful += 1`;
- сработал снова → `harmful += 1`.

Переходы после K эпизодов (`K = 5` стартово, настраивается):

| Условие | Переход |
|---|---|
| `helpful >= K` и `harmful == 0` | `confirmed` — причина устранена |
| `harmful > 0` | `regressed` — на доработку, с новым доказательством |
| ноль эпизодов с этим уроком за N дней (`N = 30`) | `dormant` |
| `dormant` и ablation показала «без него не хуже» | `retired` |
| новый факт противоречит уроку | `superseded_by: <id>`, старый **не удаляется** |

Три свойства этой петли:

- **Урок не влияет ни на что, пока `proposed`.** Влияние начинается только
  после мержа интервенции человеком.
- **`retired` и `superseded` остаются в памяти и читаемы.** Принцип graphiti и
  iai-pme: вытесненный факт нужен для реконструкции, почему решение было таким.
- **`dormant` с ablation** — приём SKILL.nb против распухания playbook и
  взаимных помех между уроками.

Это и есть цикл отслеживания «была ли ошибка исправлена».

## Сбои

| Сбой | Признак | Как ловится |
|---|---|---|
| Судья вышел нулём без артефакта | нет файла суждений | проверка артефакта, а не кода возврата |
| Rate-limit z.ai | `judge_episode` падает или пуст | холодный такт в тихом окне, `maximum_attempts=1`, вердикт откладывается на следующее окно |
| Все суждения отброшены гейтом | пустой `findings` при ненулевом `score` | вердикт публикуется с пометкой `judge_unanchored`, уроков не порождает |
| Счётчики врут | `lessons_injected` пуст при активных уроках | `inject_lessons` не отработала; расхождение видно сверкой числа эпизодов |
| Память распухла | больше 15 пунктов проходят отбор постоянно | `size_gate` режет, отчёт CLI показывает вытесненные |
| Петля оптимизирует не то | `score` растёт, `line_survival` падает | вес `pr_merged` в свёртке ограничен, обе величины в отчёте рядом |

## Тестирование

Модульные — на детерминированные части: свёртка сигналов, разрешение якорей,
переходы статусов, отбор при превышении потолка, дельта-операции.

Гейты — на образцах: суждение с несуществующим `file:line`, урок без
`trigger_signal`, правка промпта с изменённой целью стадии.

**Проверка живым прогоном обязательна.** Модульные тесты этот класс отказов не
видят: он на стыках. Заводится Issue на мелкую доработку, прогон доводится до
PR, дальше проверяется:

1. эпизод записан, `intent` не пуст;
2. `lessons_injected` соответствует тому, что реально попало в постановку;
3. холодный такт стартовал и дождался мержа;
4. в вердикте есть хотя бы одно суждение с разрешимым якорем;
5. счётчик урока сдвинулся на следующем прогоне.

Смотреть три поверхности сразу — Temporal, Sentry, комментарии в Issue.

## Что не входит в первый срез

- Граф и вектор-индекс. Подключаются позже поверх той же markdown-истины, когда
  память перестанет читаться грепом.
- Фазы Issue и Delivery. У них другие мерила качества, и это отдельный разговор.
- Автоматический мерж правок промптов. Человек остаётся гейтом.
- Полный перебор GEPA по промптам. Дорого; начинаем одиночными дельтами.
- Парето-фронт кандидатов. Нужен, когда кандидатов много; на одиночных дельтах
  избыточен.
- Оптимизация кода активностей. Только промпты, гварды и тесты.

## Выкладка

`poh-reflection` подключается в `poh-issue-agents` зависимостью. Память —
отдельный клон на стенде, запись коммитом в ветку, публикация PR'ом; прямой
пуш в `main` памяти запрещён так же, как в контуре.

Пин сборки на стенде — полным SHA, как и для остального контура: BuildKit
кэширует git-клон по URL и после нового коммита в ту же ветку молча собирает
прежний код.
