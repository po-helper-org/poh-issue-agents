# Навык: entire — память прогонов

## Что это

`entire` записывает твой диалог: промпты, ответы, изменения файлов — и
складывает их **чекпоинтами в git-рефы того же репозитория**, над которым ты
работаешь. Получается ветка вида `entire/<hash>`, которая уезжает в origin
рядом с артефактами.

Ничего никуда не отправляется наружу: аккаунт не нужен, запись локальная,
хранилище — сам git. Для тебя это значит, что контекст прошлой работы лежит
там же, где код, и достаётся теми же средствами.

**Почему это важно в контуре.** Прогоны здесь рвутся: провайдер отвечает 524,
кончается лимит запросов, стенд передеплоивают посреди работы. Артефакты
показывают РЕЗУЛЬТАТ, но не путь к нему — по `concept.md` не видно, какие
варианты уже отвергли и почему. Чекпоинты сохраняют именно это.

## Когда обращаться

| Ситуация | Что делать |
|---|---|
| Получил `/bft-deep <id>` | Прогон уже поднял сессию сам. Загляни в неё, если непонятен контекст артефактов |
| Продолжаешь оборванную работу | `entire session list` → найти сессию → `entire checkpoint list` |
| Видишь артефакт без объяснения | `entire checkpoint search "<тема>"` — как к нему пришли |
| Не помнишь, что уже пробовали | `entire recap` — сводка недавней активности |
| Нужна причина решения | `entire checkpoint explain <id|sha>` |

Не зови его просто так: если задача самодостаточна и вход полон, чекпоинты —
лишний контекст, который вытеснит из окна то, что действительно нужно.

## Как взаимодействовать

**Единственный достоверный источник по командам — сам CLI:**

```
entire agent-help              # что вообще умеет
entire agent-help <команда>    # точные флаги установленной версии
```

Читай его, а не память: флаги меняются между версиями, а `agent-help` всегда
соответствует установленному бинарю. Добавь `--json` к любой команде, если
разбираешь вывод программно.

Рабочий минимум:

```
entire session list                  # какие сессии есть, с их id
entire session info <id>             # подробности сессии
entire checkpoint list               # чекпоинты текущей ветки
entire checkpoint search "<запрос>"  # поиск по смыслу и по словам
entire checkpoint explain <id|sha>   # чем занимался этот чекпоинт
entire recap                         # сводка недавней активности
```

Репозиторий определяется автоматически по origin — **не спрашивай его имя и не
подставляй `--repo`**, если только не целишься в ДРУГОЙ репозиторий.

## Границы, о которых надо знать

**entire видит только агента.** Он цепляется хуками за сессию Claude Code.
Стадии контура, переведённые на прямые вызовы модели (`BFT_DIRECT_STAGES`),
сессии не имеют — их работы для чекпоинтов не существует. Что делали они,
написано в `artefacts/dialog-log.md` рядом с артефактами.

**Чекпоинты — не артефакты.** Требования, документ и валидация живут в ветке
`bft-research/issue-N` и остаются источником истины. Чекпоинты объясняют, как к
ним пришли, но не заменяют их: не цитируй рассуждение из чекпоинта как принятое
решение, если оно не доехало до артефакта.

**Запись ведётся сама.** Хуки ставит контур перед первой стадией
(`entire enable --agent claude-code`); включать её руками не нужно, и выключать
тоже — `entire disable` оставит следующий прогон без памяти.
